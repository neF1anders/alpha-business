# Загрузка CSV и PDF в PostgreSQL

Цель: подготовить профили и связи компаний, извлечь текст аналитики и предоставить
коллегам фрагменты для retrieval с точными ссылками на файл и страницу.
Исходные CSV/PDF остаются в `data/raw/`. Обработка выполняется локально, без отправки
содержимого во внешние OCR/LLM API.

## Быстрый запуск в Windows / PowerShell

Нужен запущенный Docker Desktop с Linux containers. Все команды — из корня проекта.

1. Скопируйте `.env.example` в `.env` и задайте `POSTGRES_PASSWORD`.
2. Поднимите БД и соберите контейнер обработки:

```powershell
Copy-Item .env.example .env
# Отредактируйте POSTGRES_PASSWORD в .env до запуска.
docker compose up -d db
docker compose build ingest
docker compose run --rm ingest init-db
```

3. Очистите CSV, проверьте отчёт и загрузите результат:

```powershell
docker compose run --rm ingest prepare-csv
Get-Content -Encoding utf8 data/processed/csv/manifest.json
docker compose run --rm ingest load-csv
```

4. Распознайте PDF и загрузите страницы и фрагменты:

```powershell
docker compose run --rm ingest extract-pdfs --metadata data/reports-metadata.json
Get-Content -Encoding utf8 data/processed/pdf/report.json
docker compose run --rm ingest prepare-news
docker compose run --rm ingest tag-chunks
docker compose run --rm ingest load-pdfs
docker compose run --rm ingest load-news
docker compose run --rm ingest search "ключевая ставка"
```

Переходите к следующей команде только после успешного завершения предыдущей.
OCR 64 страниц может занять несколько минут. Отображается прогресс по страницам.
`extract-pdfs` сохраняет кэш: повторный запуск продолжит работу с готовых страниц.
При изменении настроек или версии OCR создаётся отдельный кэш.

БД доступна на `localhost:5432`, база и пользователь `insights`, пароль из `.env`.
Для остановки: `docker compose stop`. Данные лежат в именованном Docker volume;
`docker compose down -v` удаляет их, поэтому для обычной остановки эту команду не используйте.

## Запуск Python без контейнера

Python 3.12+; для PDF нужен Tesseract с языками `rus` и `eng`.
Docker-образ уже содержит Tesseract и оба языка. Для Windows можно установить
Tesseract отдельно и передать путь через `--tesseract`.

```powershell
uv venv
uv sync --extra ml
uv run python -m ingestion prepare-csv
uv run python -m ingestion extract-pdfs --metadata data/reports-metadata.json --tesseract "C:/Program Files/Tesseract-OCR/tesseract.exe"
uv run python -m ingestion prepare-news
uv run python -m ingestion tag-chunks
$env:PGHOST = "localhost"
$env:PGPORT = "5432"
$env:PGDATABASE = "insights"
$env:PGUSER = "insights"
$env:PGPASSWORD = "пароль из .env"
uv run python -m ingestion init-db
uv run python -m ingestion load-csv
uv run python -m ingestion load-pdfs
uv run python -m ingestion load-news
```

Вместо `PG*` поддерживается `DATABASE_URL`. Локальный Python сам `.env` не читает;
Compose читает его. Не включайте пароль в коммит.

## Правила очистки CSV

CSV читаются потоково с `utf-8-sig` и разделителем `;`. Для выявления конфликтов
используется временная SQLite на диске; весь миллион платежей не загружается в память.

| Ситуация | Действие |
|---|---|
| Один `SYNTHETIC_U`, разные профили | Удалить все профили этого ID и все платежи/связи, ссылающиеся на него |
| Полностью одинаковые записи после нормализации | Оставить одну |
| `PAYER = BENEFICIARY` | Удалить платёж |
| Одна направленная пара, разные сумма/количество | Удалить все строки пары: период неизвестен, суммирование может задвоить оборот |
| ID контрагента или связанной компании без карточки | Сохранить связь и создать сущность без профиля |
| Некорректный ID, числовое значение, неположительный платёж, дробное количество | Исключить строку |
| Неправильный заголовок / отсутствующий исходный файл | Остановить подготовку |

Политика повторяющихся платёжных пар намеренно консервативна для MVP. Причины
отбраковки имеют приоритет: конфликт компании → перевод себе → конфликт пары → дубль.
Каждая исключённая строка получает ровно одну причину.

Артефакты `data/processed/csv/`:

- `companies.csv`, `person_links.csv`, `payments.csv` — очищенные данные;
- `SOURCE_ROW` — номер исходной записи, считая заголовок первой записью
  (при многострочных полях это не физический номер строки файла);
- `rejected.jsonl` — исходная запись, файл, номер и причина исключения;
- `manifest.json` — количество строк, конфликтные ID и SHA-256 входов/выходов.

Значения сохраняются по уточнённому словарю: `NEGATIVEMARK` — признак ключевого
собственника; `CITY_NAME` и `RC_NAME` — место проживания физлица; `FTS_FLAG` — наличие
сведений в ФТС. Сведения о странах не доказывают направление импорта/экспорта.
Никакого отрицательного риск-скоринга из `NEGATIVEMARK` не строится.

ОКВЭД и идентификаторы остаются строками. Флаги преобразуются в `0/1`, в БД — boolean.
Пустые значения становятся SQL NULL. Денежные величины загружаются в точный numeric.
Годовая выручка `1000` сохраняется: её трактовка как NULL присутствует в старом DSL,
но не подтверждена уточнённым словарём. Валюта/единицы и период платежей не выдумываются.
Несовпадение FTS_FLAG и списка стран и отсутствующие признаки не являются причиной
удаления всей компании.

`load-csv` проверяет контрольные суммы и заменяет три таблицы и реестр сущностей
как единый снимок в одной транзакции. При ошибке предыдущий снимок остаётся целым.
Повторная загрузка идентичного манифеста пропускается. Это режим для одного набора
хакатона, не накопительная загрузка платежей за несколько периодов.

## PDF → страницы → фрагменты

1. Сначала пробуем извлечь текстовый слой через PyMuPDF.
2. Для страницы с менее чем 40 символами текстового слоя выполняется рендер в 250 dpi
   и Tesseract `rus+eng`, `--psm 3` (автоматическая сегментация колонок).
3. Из TSV распознавания собираются слова → строки → абзацы; сохраняется средняя
   уверенность по распознанным словам (0–100).
4. Текст делится внутри страницы: до 1400 символов, перекрытие около 200 символов,
   предпочтительно на границах предложений/абзацев. Смещения позволяют найти фрагмент
   в полном тексте страницы.
5. Пустые страницы и OCR с уверенностью ниже 60 отмечаются `needs_review=true`.
6. Загружаются только законченные документы `*.pdf.json`; кэш отдельных страниц
   напрямую не импортируется. Обновление каждого документа атомарно.

Параметры: `--dpi`, `--psm`, `--languages`, `--chunk-size`, `--overlap`,
`--min-confidence`, `--timeout`, `--force-ocr`. Последний полезен для смешанных PDF,
где текстовый слой покрывает только часть страницы. У имеющихся PDF текстового слоя нет.

Файл `data/reports-metadata.json` содержит названия и вручную проверенные даты.
Неизвестные даты остаются null. Месяц в заголовке обзора не считается датой публикации.
Материал 2021 года сохраняется с собственной датой. После изменения метаданных
повторите extract-pdfs, tag-chunks и load-pdfs; готовые страницы будут взяты из кэша.

Оценка OCR — качество распознавания символов, а не проверка истинности утверждений.
Tesseract может ошибаться в колонках, знаках %, десятичных разделителях, таблицах
и графиках. Порог не гарантирует корректность. Для MVP нужно выборочно проверить
цифры и порядок абзацев; сложные таблицы/графики требуют отдельного анализатора
структуры или мультимодальной модели. Чанки пока не разделяются на факт/прогноз/мнение.

## Что получают коллеги

Подготовка JSONL и теги для PDF/новостей описаны в [tagging.md](tagging.md).
Загрузчики документов по умолчанию читают `data/processed/tagged/pdf/` и
`data/processed/tagged/news/`, созданные командой `tag-chunks`.

| Таблица/представление | Назначение |
|---|---|
| `insights.company_entities` | Все известные ID компаний, включая контрагентов без карточек |
| `insights.companies` | 24 исходных поля карточки в нижнем регистре + source_row |
| `insights.person_links` | Связи физлиц с компаниями и география проживания |
| `insights.payments` | Направленные связи payer → beneficiary, сумма и количество |
| `insights.csv_snapshot` | Манифест текущего набора и время загрузки |
| `insights.documents` | Файл, SHA-256, название, дата, настройки извлечения |
| `insights.document_pages` | Полный текст страниц, способ извлечения, качество |
| `insights.document_chunks` | Все фрагменты и смещения, включая страницы для проверки |
| `insights.rag_chunks` | Фрагменты, доступные для retrieval; страницы needs_review исключены |

Примеры запросов находятся в `sql/retrieval_examples.sql`. В результатах поиска
возвращайте `source_file`, `page_number` и `published_at` вместе с текстом.
Полнотекстовый поиск использует русскую морфологию PostgreSQL и GIN-индекс.
Семантических векторов в MVP нет: размерность и модель должны совпадать у индексатора
и retriever. Образ БД содержит pgvector; после выбора модели коллеги могут создать
таблицу embeddings с FK на `document_chunks.chunk_id`, названием/версией модели,
`vector(N)` и `ON DELETE CASCADE`. При изменении текста старые векторы должны удаляться.
CSV остаются реляционными данными для SQL-фильтров и графа, а не текстовыми чанками.

## Проверки

```powershell
uv run python -m unittest discover -s tests -v
```

Проверка с настоящими Tesseract и PostgreSQL в контейнере:

```powershell
docker compose run --rm -e RUN_DB_TESTS=1 --entrypoint python ingest -m unittest discover -s tests -v
```

Интеграционный тест создаёт отдельную случайно названную БД `insights_test_*`
и удаляет только её. Пользователю БД требуется право CREATEDB (у пользователя
из данного Compose оно есть). Без `RUN_DB_TESTS=1` тест БД пропускается;
без Tesseract пропускается проверка настоящего OCR.

Проверяются фильтрация конфликтов/дублей, сохранение неизвестных контрагентов,
точность идентификаторов и ОКВЭД, бухгалтерия исключённых строк, повторный запуск,
покрытие текста чанками, смещения, чтение TSV и кэш OCR. В модульном тесте OCR
подменяется фиксированным результатом; отдельный тест распознаёт настоящую растровую
страницу через Tesseract. Тест БД проверяет COPY, неизвестных контрагентов, точность
денежной суммы, повторный импорт, откат при ошибке и поисковую выдачу.
