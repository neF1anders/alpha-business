# Новостной поиск: запуск и контракт

## Что подключено

`company_tags.csv + companies.mainokved_name → кандидаты новостей → реранкер → основания из PDF → API`.
Композиция: `orchestrator.main.create_default_app`. Порт: `NewsRetriever.retrieve(NewsQuery)`.
PR включает оркестратор из командной ветки `company_profiles`, которого пока нет в `main`.

- `lexical` (по умолчанию): PostgreSQL FTS, правила сопоставления тегов, `TagReranker`.
- `local_semantic` (явное включение): три запроса по деятельности и темам мониторинга;
  E5 top-40 на запрос + FTS top-40; round-robin объединение без повторения IDs,
  до 80 кандидатов; cross-encoder и подавление дублей заголовка за один UTC-день.
- Баннеры: до 3 новостей. Чат: до 5. Вопрос чата и отсутствие деятельности компании
  сохраняют лексический путь; семантический поиск чата пока не подключён.
- Банк: отдельный поиск контекста для каждого отобранного события. Это дополнительный
  материал, а не автоматическое доказательство влияния события на компанию.
- Ответы использующейся `TemplateSummaryBranch` отмечены `raw_news=true`.
  LLM-анализ бизнес-влияния и генерация персональных рекомендаций сюда не входят.

## Данные и базовый запуск

Python 3.12 и PostgreSQL 17. Сначала подготовьте таблицы компаний/платежей и PDF
по основному README. Подключение — стандартные `PGHOST`, `PGPORT`, `PGDATABASE`,
`PGUSER` и защищённый `PGPASSFILE`, либо `DATABASE_URL` в окружении.
Python-команды сами `.env` не загружают. Не вставляйте пароль в команды или Git.

```sh
uv sync
uv run python -m ingestion init-db
```

Новости для API хранятся в `insights.news_articles`, отдельно от аналитических
`rag_chunks`. Нужен ранее собранный snapshot с `news.jsonl`, `report.json`,
`receipts.jsonl`, `audit.json` и исходными HTML. Его передают отдельно в приватном
канале команды, например сохраняют в `.local/news-snapshot/`; один JSONL или ZIP
без остальных файлов не является готовым входом этого импортера.

```sh
uv run python -m ingestion.news_audit --snapshot .local/news-snapshot --allow-partial
uv run python -m ingestion load-news --format snapshot --source .local/news-snapshot
uv run python -m scripts.build_tags --from-db
uv run python -m orchestrator
```

`--allow-partial` разрешает проверить сохранённые статьи, если сборщик не достиг
заданного числа; ошибки контрольных сумм и содержимого по-прежнему блокируют аудит.
Импорт атомарен и повторяем: одинаковые статьи пропускаются, изменение ранее
сохранённого текста приводит к rollback. Исходный snapshot не удаляется.
Старый `load-news --format chunks` сохранён для командного JSONL-процесса и грузит
аналитические чанки; это другой формат и он не заполняет `news_articles`.

На macOS вместо Docker можно использовать `uv run python scripts/local.py start`, затем
запускать команды через `uv run python scripts/local.py run python …`.
Runner создаёт отдельный PostgreSQL с приватным Unix-сокетом в `.local/` и
принудительно выбирает именно его. Требуется установленный Homebrew PostgreSQL 17.

HTTP: `http://127.0.0.1:8000/docs`. Пример для существующего company ID:

```sh
curl --fail http://127.0.0.1:8000/v1/banners \
  -H 'Content-Type: application/json' -d '{"company_id":"U_1"}'
```

`COMPANY_TAGS_PATH` по умолчанию `data/processed/company_tags.csv`.
`REPORTS_PATH` по умолчанию `data/raw/reports`; это каталог исходных PDF.
Для Docker задайте путь PDF на хосте: Compose монтирует его read-only.
Docker-образ оркестратора содержит только лексический backend. Семантический режим
ниже запускается в Python-окружении на хосте; веса не включены в Docker-образ.

## Включить семантическую ленту

```sh
uv sync --extra ml
uv run python -m retrieval.semantic download
uv run python -m retrieval.reranker download
uv run python -m retrieval.semantic index
NEWS_SEARCH_MODE=local_semantic NEWS_CANDIDATE_LIMIT=80 uv run python -m orchestrator
```

В PowerShell переменные задаются отдельно через `$env:NEWS_SEARCH_MODE='local_semantic'`
и `$env:NEWS_CANDIDATE_LIMIT='80'`. Для Mac runner добавьте `scripts/local.py run python`
после `uv run python` в командах, которым нужна локальная БД.

E5: `intfloat/multilingual-e5-small`, 384 измерения, mean pooling + L2,
префиксы `query:`/`passage:`, окна до 512 токенов с перекрытием. Cross-encoder:
`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, заголовок и первые 2400 символов текста,
не более 512 токенов пары. Полный исходный текст не обрезается в базе.
Ревизии моделей зафиксированы в коде; загрузка разрешена только явными командами
`download`. При обслуживании запросов inference офлайн, remote code отключён.
Поддержаны CPU и Apple MPS; CUDA в этой реализации пока не выбирается.

Индекс сохраняется в `insights.news_embeddings`; загрузчик проверяет рецепт,
контрольные суммы текстов и полноту чанков. Поиск — точный cosine по снимку в RAM,
без отдельного векторного сервера. Для текущих нескольких тысяч статей этого достаточно.
После загрузки новых статей повторите `index` и перезапустите API. До перезапуска
новые статьи доступны лишь лексическому каналу. Изменение старого текста требует
отдельной миграции индекса: загрузчик намеренно не перезаписывает его молча.

`NEWS_CANDIDATE_LIMIT`: целое 1–100, по умолчанию 80; применяется к семантическому
режиму. Дополнительные контекстные запросы экспериментальны и в композиции отключены.
Коэффициенты ранжирования не являются вероятностью полезности или бизнес-влияния;
порога уверенного отказа у cross-encoder пока нет.

## Контракт и ограничения

`NewsQuery`: теги, необязательный `question`, `company`, `limit`, `as_of`,
`published_after`. По умолчанию текущее время и последние 90 дней. Даты должны
содержать часовой пояс. HTTP API использует текущее время; фиксированный срез
доступен через Python-контракт для воспроизводимой оценки.
`RetrievalResult`: новости с ID, URL, датой, текстом, тегами и retrieval score.
Для dense-only статей теги могут быть пустыми: отсутствие правил не исключает их.

SQL параметризован, чтение выполняется в read-only транзакциях с таймаутами;
локальные модели защищены от конкурентного повторного входа. Занятая модель или
истёкший deadline возвращают деградированный ответ, а не скрытую очередь.
PDF выдаются только по зарегистрированным ID внутри `REPORTS_PATH`, с проверкой
обхода пути и симлинков. Отсутствующие файлы не публикуются как доступные основания.

Сервис пока предназначен для локального прототипа: нет аутентификации и проверки
доступа пользователя к company_id. Для сетевого размещения это необходимо добавить.
Исторические публикации отсеиваются консервативной эвристикой; заголовочные дубли
не заменяют семантическую кластеризацию событий. Теги факторов — подсказки для поиска,
а не доказательство конкретных договоров, поставщиков или валютной зависимости.

## Проверка

```sh
uv run python -m unittest discover -s tests -q
RUN_DB_TESTS=1 uv run python -m unittest discover -s tests -q
```

Для полного набора нужны зависимости обработки, оркестратора и семантики, Tesseract
с `rus+eng` и PostgreSQL. DB-тесты требуют отдельной тестовой роли с `CREATEDB` и
создают/удаляют случайно названные тестовые базы. Не выдавайте это право роли API.
На Mac для DB-тестов используйте local runner. Веса моделей для unit-тестов не нужны.

Утилита `python -m evaluation` считает pooled Recall@K, Precision@K, nDCG@K, MRR,
отказы на отрицательных примерах и latency p50/p95. Форматы:

```json
{"query_id":"company-example","doc_id":"news-example","grade":2}
```

```json
{"query_id":"company-example","ranking":["news-example"],"latency_ms":25}
```

Каждая строка — отдельная JSON-запись в qrels/run соответственно. Необходима
разметка человеком: 0 — нет связи, 1 — общий фон, 2 — полезно, 3 — прямо значимо.

```sh
uv run python -m evaluation --qrels .local/qrels.jsonl --run .local/run.jsonl \
  --k 5 --min-relevant-grade 2 --unjudged-policy error
```

Считайте @80 до реранкера и @5 после него по отдельным run-файлам. Неизвестные
оценки должны блокировать итоговую проверку (`error`), а не становиться нулями.
Recall относится к размеченному пулу. nDCG здесь использует gains `2**grade-1`,
включая слабую связь grade=1; это явно отличается от отдельных локальных экспериментов.
Макросредние ranking-метрик исключают запросы без полезных документов: они оцениваются
отдельно как abstention. Для сравнения фиксируйте корпус, дату, конфигурацию и qrels.

Предварительные локальные результаты не считаются независимой оценкой: известные
25 полезных пар находились все в top-80, но на новом малом пилоте — только 2 из 3.
Качество финальной выдачи требует командной разметки. Ни эти отчёты, ни 500-парный
набор разметки, ни экспериментальные варианты реранкера в этот PR не включены.
