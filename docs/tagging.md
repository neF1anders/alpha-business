# Новости JSON/JSONL и теги чанков

## Команды

Для `news_combined.jsonl` с неполными материалами см.
[отдельную инструкцию](news-combined.md). Команды ниже относятся к прежнему
набору `news.jsonl` и строгому фильтру качества.

```powershell
docker compose build ingest
docker compose run --rm ingest init-db
docker compose run --rm ingest prepare-news
docker compose run --rm ingest tag-chunks
docker compose run --rm ingest load-pdfs
docker compose run --rm ingest load-news
```

До `tag-chunks` должны быть очищенные `data/processed/csv/companies.csv`,
подготовленные PDF в `data/processed/pdf/` и/или новости в `data/processed/news/`.
PDF повторно распознавать не нужно, если готовые артефакты уже есть.
`init-db` применяет добавочную миграцию существующей БД; старые записи сохраняются.

Вне Docker установите зависимости: `uv sync --extra ml`.
Затем используйте `uv run python -m ingestion` вместо
`docker compose run --rm ingest`. Первый запуск скачивает модель Hugging Face;
тексты не отправляются во внешнюю API. Параметр `--revision` позволяет закрепить
ревизию модели. В метаданных сохраняется ревизия, доступная из модели, либо
переданная через этот параметр; без них поле может быть null. Для воспроизводимых
запусков при обновлении весов указывайте конкретный commit модели через `--revision`.

## Что читает prepare-news

По умолчанию `data/raw/reports/news.jsonl`: одна новость на строке.
Поддерживается также JSON-массив или объект `{"news": [...]}` через `--source`.
Обязательные поля: `news_id`, `title`, `url`, `text`.
В режиме `--include-partial` пустой `text` допускается для статусов
`metadata_only` и `short_excerpt`: используется заголовок. Если текст анонса
есть, чанк строится из заголовка и анонса. Полный текст статьи сохраняется как прежде.
`--dry-run` выполняет ту же проверку и подсчёт чанков без записи файлов и без модели.
URL должен быть HTTP(S). Дата `published_at` — ISO 8601; неизвестная дата остаётся null.
Дата со временем и часовым поясом сохраняется в `published_at_timestamp`;
исходное значение сохраняется в `source_metadata` (в том числе дата без часового пояса).

В предоставленном файле 5 878 статей от «Коммерсанта» и Банка России.
Текст уже извлечён: OCR не вызывается. Текст нарезается тем же алгоритмом, что PDF:
1400 символов, около 200 символов перекрытия, точные смещения в исходном тексте секции.
`--chunk-size` и `--overlap` позволяют изменить размер.

Сохраняются идентификатор новости, URL, издатель, дата и метаданные сборщика.
Рубрики `categories` сохраняются как метаданные источника, но не считаются нашими тегами.
По умолчанию `retrieval_eligible=false` и `duplicate_of` исключают запись;
непустые `quality_flags` помечают секцию `needs_review`.
`--include-partial` явно допускает неполные материалы в retrieval для статусов
`metadata_only` и `short_excerpt`. Флаги неполноты и минутной точности времени
не требуют проверки в этом режиме; другие флаги качества по-прежнему выставляют
`needs_review`. Дубли исключаются в обоих режимах. Исходные флаги и запрет сборщика
сохраняются в `source_metadata`, применённая политика — в `source_metadata.ingestion`.
Для каждой статьи создаётся одна логическая секция
`page_number=1`; это не физическая страница сайта. В интерфейсе показывайте её URL.

Точные повторы записей/текста/URL пропускаются; конфликтующие записи с одним news_id
исключаются. Ошибки строк JSONL и некорректные записи попадают в `rejected.jsonl`.
Текстовые SHA-256 вычисляются заново. Полный манифест со списком файлов и контрольными
суммами пишется после завершения подготовки. Загрузчик читает только файлы из манифеста:
артефакты, оставшиеся от прошлых запусков, не попадут в импорт случайно.
Загрузка новостей накопительная: удаление статьи из JSONL не удаляет автоматически
уже загруженный документ из PostgreSQL.

## Контракт тегов

`tags` — массив строк с регистрозависимым сравнением. Только четыре пространства:
`factor`, `sector`, `country`, `region`. `labor` и `okved` из предыдущего варианта
списка не используются. На каждый чанк сохраняются все пять флагов (0/1 в JSON,
boolean в PostgreSQL), даже если ни один тег не найден.

| Флаг | Правило для текста чанка |
|---|---|
| `key_rate` | Упоминание ключевой ставки; наличие слова «кредит» само по себе недостаточно |
| `fx` | Распознанное упоминание иностранной страны, включая прилагательное/алиас; одно упоминание России не включает флаг |
| `commodities` | Упоминания сырья, добычи, агросектора, металлов, энергетики |
| `consumer_demand` | Упоминания потребительского спроса/потребления, розницы, общепита, гостиниц и связанных услуг |
| `construction_market` | Упоминания строительства, жилья, недвижимости, застройщиков, ипотеки |

Флаг 1 добавляет соответствующий `factor:*`; флаг 0 означает, что правило ничего
не обнаружило. Это не доказательство отсутствия темы. Используется морфология
русского языка (`pymorphy3`) и явные правила в `src/backend/ingestion/domain/taxonomy.py`.
Правила компаний по кредитам и продуктам на новостной текст не переносятся.
Разметка использует только текст конкретного чанка; соседняя страница не добавляет
упоминаний. Для неполных новостей заголовок входит в подготовленный текст явно;
для полных статей отдельно сохранённый заголовок не добавляет теги к чанкам.

### Страны и регионы

Канонические значения читаются из очищенного CSV компаний: все непустые страны
из `FTS_COUNTRY_NAME` и регионы из `REGION`. Учитываются также строки с FTS_FLAG=0,
поскольку флаг иногда противоречит заполненному списку стран. В текущем снимке
получаются 128 стран и 82 региона. Регистр и написание выводятся ровно как в CSV.

Для распознавания учитываются падежи («в Китае» → `country:КИТАЙ`), заданные
алиасы («КНР», «китайский»), перестановка слова «Республика» и несколько исторических
названий («Башкирия» → `region:Башкортостан (Республика)`). Словарь алиасов открыт
для дополнений. Города не превращаются автоматически в регионы; «Москва» не
совпадает с «Московская область».

`country_mentions` сохраняет все распознанные страны; `unmapped_countries` — те,
для которых нет канонического тега компаний (например, Россия и Украина).
Они не порождают несуществующий `country:*`, но иностранные упоминания включают `fx`.
Список дополнительных названий небольшой: обнаружение всех возможных топонимов,
прилагательных и метонимий не гарантируется. Отчёт позволяет расширять словарь.
Теги сообщают об упоминании, а не о направлении импорта/экспорта или влиянии на компанию.

### Отрасль sector

Используется локальная модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
Эмбеддинг чанка сравнивается косинусной близостью с описаниями всех 19 отраслей.
Полные определения и диапазоны ОКВЭД находятся в `src/backend/ingestion/domain/taxonomy.py`.
У модели лимит 128 токенов: длинный чанк разбивается на окна, нормированные векторы
окон усредняются с весом по числу токенов и снова нормируются. Хвост текста учитывается.

Сохраняются максимум один принятый `sector:*`, его диапазон (`okved_range`),
оценка сходства и три лучших кандидата. По умолчанию:

- `--threshold 0.30`: минимальная близость;
- `--margin 0.03`: минимальный отрыв от второго кандидата.

Если критерии не выполнены, `sector.value=null`, тега отрасли нет. Общеполитический
текст не обязан относиться к отрасли. Эти пороги — стартовая эвристика, не оценка
вероятности и не обученный на ваших новостях классификатор. Несколько тем в одном
чанке могут дать неоднозначный результат; кандидаты сохранены для проверки.
Для улучшения качества соберите размеченную выборку и измеряйте точность по секторам.
CatBoost можно обучать на такой выборке позже; сейчас целевых меток для обучения нет.

Векторы модели используются только для классификации отрасли. Retrieval-эмбеддинги
в pgvector этим шагом не создаются.

## Артефакты и БД

Разметка не меняет исходные OCR/JSON-артефакты: создаются
`data/processed/tagged/pdf/` и `data/processed/tagged/news/` с манифестами.
`--news-only` исключает PDF из обработки и не меняет их файлы или манифест;
общий `report.json` при таком запуске описывает только обработанные новости.
`load-pdfs` и `load-news` по умолчанию читают эти директории. Старый путь можно
явно передать через `--source`, но в неразмеченных файлах тегов нет.
Результаты классификации и веса модели находятся в `data/cache/` и не попадают в Git.

В `insights.document_chunks` добавлены `tags`, пять boolean-флагов,
`tagging_version` и `tag_metadata`. В `tag_metadata` — сектор, его score и кандидаты,
страны/регионы и параметры классификатора. Старые неразмеченные строки имеют
`tagging_version IS NULL`; их значения false не означают, что классификатор их проверил.
Поле `tags` индексируется GIN; те же поля доступны в `insights.rag_chunks`.

```sql
SELECT source_file, source_url, page_number, tags, text
FROM insights.rag_chunks
WHERE tags @> ARRAY['factor:fx', 'country:КИТАЙ']::text[];

-- Совпадение хотя бы с одним тегом компании:
SELECT chunk_id, tags, text
FROM insights.rag_chunks
WHERE tags && ARRAY['sector:construction', 'factor:key_rate']::text[];
```

В CLI `--tag` повторяется для AND-фильтра:

```powershell
docker compose run --rm ingest search "нефть" --tag "factor:commodities" --tag "country:КИТАЙ"
```

Отчёт `data/processed/tagged/report.json` показывает частоты тегов, число чанков без
принятой отрасли и страны вне словаря. Версия разметки зависит от кода правил,
CSV-словаря, модели, её ревизии и порогов. Кэш повторно используется только при
совпадении версии и текста. При обновлении тегов существующие chunk_id сохраняются;
изменившиеся/исчезнувшие фрагменты удаляются при обновлении документа транзакционно.

Техническая основа: [Sentence Transformers: семантическое сходство](https://sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html),
[описание мультиязычной модели и её лимита](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2).
